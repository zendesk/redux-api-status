# redux-api-status

A Redux utility library for tracking API/promise request statuses. Provides actions, reducers, and selectors to manage the lifecycle of async requests (pending, loaded, failed, cancelled) in a Redux store.

## Setup & Commands

```bash
# Install dependencies
yarn install

# Run tests
yarn test

# Run tests in watch mode
yarn test:watch

# Build (UMD bundle + Babel-compiled module)
yarn build

# Build UMD bundle only
yarn build:main

# Build Babel-compiled module only
yarn build:module

# Publish to npm (builds first, then publishes from lib/)
yarn dist

# Regenerate docs table of contents
yarn docs
```

## Code Conventions

- Language: ES2015/ES2017 JavaScript with Babel transforms (object rest/spread, async/await via generators)
- File naming: `kebab-case.js` for source files, `kebab-case.test.js` for test files
- Test files colocated with source files (e.g. `src/actions/actions.test.js` alongside `src/actions/actions.js`)
- Public API is exported from `src/index.js` — keep exports stable; this is a published npm library
- Action types follow the pattern `${ref}/${STATUS}` (e.g. `TODO/FETCH/1/BEGIN`)
- Use `alexs-redux-helpers` patterns for reducers (`createDynamicReducer`, `createMetaReducer`) and selectors (`nestSelectors`)

## Testing

- Framework: Jest
- Test files: colocated with source, named `*.test.js`
- Run all tests: `yarn test`
- Tests use `jest.genMockFunction()` for `Date.now` mocking — preserve this pattern when testing timestamp behaviour
- Shared test helpers live in `src/reducer/test-helpers.js`

## Library Architecture

The **ref** (a unique string per request) is the central concept. All actions, reducers, and selectors are keyed by `ref`.

Action type helpers (`beginType`, `successType`, `failureType`, `cancelType`) must be used instead of hardcoding `${ref}/BEGIN` etc. — the format could change.

## Do

- Use `trackStatus` thunk for standard request lifecycles — it handles deduplication (skips if already pending) and optional caching
- Export new public APIs from `src/index.js`
- Use `beginType` / `successType` / `failureType` / `cancelType` helpers when listening to status actions in other reducers
- Keep reducers composable via `createMetaReducer` and `createDynamicReducer` patterns
- Write tests alongside source files with matching names
- Update `docs/` when changing actions or selectors public API
- Regenerate doc table of contents with `yarn docs` after editing `docs/*.md`

## Don't

- Don't hardcode action type strings (e.g. `"TODO/FETCH/1/BEGIN"`) — use the helper functions
- Don't assume the status slice lives at `state.status` — consumers configure it via `createStatusSelectors(getState)` and the `getStatus` option on `trackStatus`
- Don't add runtime dependencies without considering bundle size (this is a client-side library)
- Don't modify files in `lib/` — that directory is generated by the build
- Don't publish directly; use `yarn dist` which builds first
